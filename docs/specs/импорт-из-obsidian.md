# Импорт заданий из Obsidian

Статус: идея, спецификация от 9 ноября 2026 года для версии 0.6. Дизайн согласован в чате, сама спецификация ждёт проверки. Ничего не собиралось и не запускалось. Формат заметок выведен из чтения 75 реальных заметок хранилища (чтение, без записи); числа и имена ниже — решения по умолчанию.

Связано: [README](../../README.md), [спецификация версии 0.5](эксплуатация-и-api.md), [модели и база](../../Models.cs), [эндпоинты предметов](../../Endpoints/SubjectEndpoints.cs), [проверка заданий](../../Endpoints/AssignmentValidator.cs), [прежний импорт `--import-legacy`](../../LegacyImport.cs).

## Идея

У пользователя задания уже живут в Obsidian: 75 заметок в папке `ДЗ/<Предмет>/<Задание>.md`, 11 предметов. В «Зачёте» их нет, а напоминания и недельный календарь работают только по его базе. Версия 0.6 переносит задания из заметок в аккаунт «Зачёта»: предметы, названия, сроки, статусы и описания. Хранилище при этом не меняется: сервер получает только тексты файлов и ничего не пишет обратно.

Импорт запускается из браузера: кнопка «Импорт из Obsidian» в навигации, выбор папки, предпросмотр, кнопка «Добавить». Повторный импорт добавляет только новое и не трогает то, что уже есть в «Зачёте».

## Что не входит

- Запись обратно в Obsidian и синхронизация `done` в обе стороны.
- Вложения, картинки, ссылки на файлы с сайта колледжа, содержимое раздела «Мои заметки».
- Обновление уже импортированных заданий (срок, статус, описание из заметки не перезаписывают данные «Зачёта»).
- Dataview-таблицы, `_скрипт/` и всё, что не заметка задания: сервер эти файлы не читает.
- Импорт токеном API: только браузер, cookie и CSRF.
- Сопоставление с заданиями, заведёнными в «Зачёте» вручную: ключ есть только у импортированных.

## Как это работает

1. Диалог «Импорт из Obsidian» предлагает «Выбрать папку» (`<input type="file" webkitdirectory>`) и «Выбрать файлы» (для телефонов, где папку выбрать нельзя). Браузер отбирает файлы `.md`, пропуская скрытые папки (имя начинается с точки), читает их как UTF-8 и отправляет JSON.
2. `POST /api/import/obsidian/preview` разбирает заметки и **ничего не записывает**. Ответ: сколько новых, сколько уже есть, список пропущенных с причинами, новые предметы, сколько описаний обрезано.
3. Пользователь смотрит предпросмотр и нажимает «Добавить»: `POST /api/import/obsidian` с теми же файлами. Сервер разбирает их заново, не доверяя предпросмотру, и пишет всё одной транзакцией.
4. Диалог показывает итог («Добавлено 34 задания, 2 новых предмета») и обновляет списки.

Тело запроса:

```json
{ "files": [ { "path": "ДЗ/ИКТ/Лабораторная работа 1.md", "text": "---\ntype: homework\n…" } ],
  "defaultDue": "2026-12-31" }
```

`defaultDue` необязателен: срок для заметок, где `due:` пуст. Без него такие заметки пропускаются.

## Разбор заметки

Шапка — блок между строками `---` в начале файла. Разбор простой, без библиотеки YAML: строки `ключ: значение`, значение обрезается по краям, кавычки снимаются; вложенные и многострочные значения не поддерживаются. Допустимы CRLF и BOM.

| Что в заметке | Что получается в «Зачёте» |
| --- | --- |
| `type: homework` | Признак задания. Любая другая заметка не считается заданием и в список пропусков не попадает, только в счётчик «не задания: N». |
| `subject: "[[ИКТ]]"` | Предмет `ИКТ`. Ссылка с псевдонимом `[[ИКТ\|Информатика]]` даёт `ИКТ`. Предмета нет — создаётся, цвет берётся по кругу из `blue, teal, purple, orange, pink, slate` в порядке сортировки новых имён. Совпадение с существующим — по `NameKey`, как в приложении. Имя длиннее 80 символов — пропуск. |
| первый `# Заголовок` | Название. Нет заголовка — имя файла без `.md`. Длиннее 140 символов — обрезается до 139 и `…`. |
| `due: 2026-10-06` | Срок. Формат только `ГГГГ-ММ-ДД` в диапазоне с 1 января 2000 по 31 декабря 2100. Пусто — берётся `defaultDue`, иначе пропуск «нет срока». Другое значение — пропуск «неверный срок». |
| `done: true` / `false` | `Done` / `Todo`. Нет ключа или другое значение — `Todo`. Статуса `InProgress` импорт не создаёт. |
| `removed: true` | Пропуск «удалено на сайте». |
| текст раздела `## Задание` | Описание: от строки после заголовка до следующего заголовка `##`. Лишние пустые строки по краям убираются. Больше 2000 символов — обрезается до 1999 и `…`, обрезка считается в предпросмотре. Нет раздела — пустое описание. |
| `source: https://…` | Ключ для поиска дубля (см. ниже). |

Служебная цитата «Отметка «сделал»…» и строки `**Предмет:**`, `**Срок:**` лежат вне раздела «Задание» и в описание не попадают.

### Ключ повтора

Ключ задания — `source`, обрезанный до 300 символов. Если `source` пуст или отсутствует, ключ строится из предмета, названия и срока: `имя предмета в верхнем регистре|НАЗВАНИЕ В ВЕРХНЕМ РЕГИСТРЕ|2026-10-06`. Ключ хранится в новой колонке `Assignments.ImportKey` (текст, может быть пустым). Уникальный индекс `(OwnerId, ImportKey)` с условием `ImportKey IS NOT NULL` не даёт создать один ключ дважды. Задания, созданные вручную или через API, остаются с пустым ключом. Ключ в ответах `/api/assignments` и `/api/v1/assignments` не показывается.

- Ключ уже есть у аккаунта — заметка считается «уже есть» и не меняет ничего.
- Один ключ встречается в загрузке дважды — вторая заметка пропускается («повтор в загрузке»).
- Удалённое в «Зачёте» задание при следующем импорте появится снова: его ключ ушёл вместе с записью.

## Лимиты и защита

| Что | Значение |
| --- | --- |
| Файлов в одной загрузке | не больше 200 (после отбора `.md`); больше — `400` «Выбери папку с заданиями» |
| Размер одного файла | не больше 100 КБ (в хранилище максимум 21 КБ); больше — файл пропускается с причиной |
| Размер запроса | не больше 3 МБ (в хранилище всего 293 КБ) |
| Длина пути в запросе | не больше 260 символов, иначе пропуск |
| Запросов | 10 в минуту на аккаунт, и предпросмотр, и добавление; больше — `429` |
| Доступ | только cookie и CSRF; токен API получает `401` |

Тексты и пути из файлов выводятся в интерфейсе только через `textContent`. Сервер не разбирает ничего, кроме текста: ссылок не открывает, файлов не читает. Все записи идут через EF Core, SQL из текстов не строится.

Если добавление ломается на уникальном индексе (два импорта одновременно), весь запрос откатывается и отвечает `409` «Импорт уже выполняется. Повтори через минуту». Остальные ошибки данных (пустой список файлов, неверный `defaultDue`) — `400` с `{"error": "…"}`.

## Проверка

Каждая проверка пишется раньше кода и после зелёного прогона проверяется «сломать и вернуть». Образцы заметок в тестах — тексты из реального хранилища (обезличивать нечего, это учебные задания), положенные в `tests/StudyTracker.Tests/Support/`.

- **Разбор:** обычная заметка; CRLF и BOM; ссылка с псевдонимом; пустой `due`; неверная дата; `done` в разных видах; `removed: true`; нет `## Задание`; описание 2000 и 2001 символов; заголовок 140 и 141; нет заголовка; не `homework`; нет шапки.
- **Предпросмотр:** считает новое, существующее, пропуски; ничего не пишет в базу; новые предметы без дублей.
- **Добавление:** создаёт предметы и задания с нужными статусами и сроками; повторный запуск ничего не добавляет; повтор ключа в загрузке; ручное задание с тем же названием не мешает; разные аккаунты не видят чужого; удалённое задание появляется снова.
- **Лимиты:** 200 и 201 файл; файл 100 КБ и больше; тело больше 3 МБ; 11-й запрос за минуту получает `429`.
- **Доступ:** без входа `401`; токен API `401`; без CSRF `403`.
- **Откат:** сбой в середине записи не оставляет частичного импорта (общая транзакция).
- **Интерфейс:** в Edge на тестовом аккаунте с копией 75 заметок — выбор папки, предпросмотр, добавление, повтор; ширина 320, 390 и 1440; клавиатура; смена аккаунта во время диалога.
- **Миграция:** на копии базы версии 0.5 колонка и индекс появляются, аккаунты, задания и токены целы.

## Решения по умолчанию

| Вопрос | Решение |
| --- | --- |
| Заметки без срока (в хранилище таких 13) | Пропускаются, если не указан `defaultDue`; в диалоге есть необязательное поле даты «Срок для заметок без срока» |
| Описание длиннее 2000 символов (в хранилище до 12 107) | Обрезается с `…`, в предпросмотре видно, сколько обрезано. Лимит приложения не поднимается |
| Заметки без раздела «Задание» (таких 10) | Импортируются с пустым описанием |
| Статус | Только `Done` и `Todo` |
| Предпросмотр и добавление | Два запроса; второй разбирает заметки заново |
| Уведомления | Импортированные задания попадают в обычную очередь напоминаний: будущие сроки получат напоминания, если уведомления включены |

## Риски

- **Дубли с ручными заданиями.** Задание, которое уже заведено в «Зачёте» руками, не имеет ключа, и импорт добавит его второй раз. Перед первым импортом в аккаунте лучше не держать копий тех же заданий.
- **Удалил — вернулось.** Повторный импорт не знает, что задание удалено намеренно.
- **Обрезка описаний.** Длинные решения и ответы из заметок теряются после 2000 символов; полные тексты остаются в Obsidian.
- **Простой разбор шапки.** Нестандартный YAML (многострочные значения, вложенные списки) читается неверно или пропускается; для заметок этого хранилища (шесть простых ключей и один `removed`) этого достаточно.
- **Выбор папки.** `webkitdirectory` не работает на части телефонов; запасной путь — «Выбрать файлы».
- **Напоминания.** После импорта сотни прошлых заданий не пишут в Telegram (просроченные пропускаются планировщиком), но будущие начнут, если уведомления уже включены.

## Готово, когда

- Папка `ДЗ` из хранилища даёт в предпросмотре понятную сводку; «Добавить» создаёт задания и предметы; повторный запуск добавляет ноль.
- Предпросмотр ничего не пишет; добавление атомарно.
- Описание, статус, срок и предмет совпадают с заметкой; пропуски объяснены.
- Чужой аккаунт, токен API и запрос без CSRF не могут импортировать.
- `dotnet build --nologo` без ошибок, `node --check` для всех файлов JavaScript и `dotnet test tests/StudyTracker.Tests` проходят; число проверок и время записаны в `README` как есть.
- Что не запускалось (Docker, GitHub Actions, настоящий телефон), прямо написано в `README`.
