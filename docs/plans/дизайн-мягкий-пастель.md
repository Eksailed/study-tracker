# План: новый дизайн «Мягкий пастель»

Статус: сделано, 9 ноября 2026 года. Выполнено в режиме «native» (всё сам, без субагентов), коммит и `git push origin main` после каждой задачи; проверено: 347 тестов (6 из них охранные для дизайна), Edge на ширинах 320, 390, 768, 1024 и 1440 пикселей, контраст текста скриптом по WCAG (не ниже 4,5:1), клавиатура и `prefers-reduced-motion`, Docker на `https://localhost` и `/health/ready` = 200. Не проверялось: экранные читалки, реальные телефоны, Safari и Firefox. Спецификация: [дизайн-мягкий-пастель](../specs/дизайн-мягкий-пастель.md).

Связано: [спецификация](../specs/дизайн-мягкий-пастель.md), [главная страница](../../wwwroot/index.html), [стили](../../wwwroot/app.css), [логика страницы](../../wwwroot/app.js), [проверки на C#](../../tests/StudyTracker.Tests).

## Что строим

Верхние вкладки-«таблетка» со скользящим индикатором, меню аккаунта, чипы предметов, крупные карточки заданий, кольцо прогресса, карточка «Группа», круглая кнопка «+», единый вид диалогов, входа и гостевой страницы. API, база и права не трогаются.

## Общие правила (действуют в каждой задаче)

- Никаких `style="..."` и `setAttribute('style', …)` ни в HTML, ни в строках шаблонов JS (политика `style-src 'self'`). Положение индикатора и длина кольца задаются через `element.style.<свойство> = …`, это разрешено.
- Только классы и `id`, уже известные скриптам; список сохраняемых `id` есть в спецификации. Кнопки с `data-view`, `data-summary`, `data-subject`, `data-status`, `data-scope`, `data-date`, `data-toggle`, `data-edit` остаются кнопками: `app.js` слушает один общий `click` на `document`.
- Новый `.js` или `.css` из `index.html` сразу попадает в `SHELL` в `wwwroot/sw.js`.
- Анимации входа не должны повторяться при каждой перерисовке списка (поиск, отметка, смена вкладки): `app.js` вызывает `render()` и перезаписывает `#assignment-list` целиком. Поэтому вход идёт через класс `intro` на `#app-shell` (ставится по событию `account-entered`, снимается через 1,2 с), а отметка — через класс `just-done` на одной карточке.
- Всё движение внутри `@media (prefers-reduced-motion: no-preference)`; без него элементы появляются сразу.
- `app.css` переписывается по областям: в каждой задаче заменяются правила своей области, устаревшие удаляются. К задаче 7 в нём не должно остаться классов, которых нет ни в `index.html`, ни в `*.js`.
- Перед `dotnet build` и `dotnet test` останавливаю локальный сервер на `5184` (он блокирует `StudyTracker.dll`), после задачи запускаю заново.
- Для визуальной проверки: копия `App_Data/v02` во временной папке, свой тестовый аккаунт, скрипт Playwright (`channel='msedge'`) лежит вне репозитория, в `%TEMP%\zachet-design\scripts\`. Рабочую базу и пароль пользователя не трогаю.
- В коммитах пишу по-русски, без строк об авторстве Claude.

## Что проверяем в конце (чего не покрывают тесты)

1. Очень длинное название предмета или задания (80 и 140 символов без пробелов): не ломает чипы, карточку и меню.
2. Новый аккаунт без предметов и заданий: чипов нет, «+ Предмет» виден, пустое состояние в новом стиле, кнопка «+» работает.
3. Ширина 320 px: «таблетка» прокручивается вбок, выбранная вкладка видна, кнопка «+» не закрывает последнюю карточку.
4. Владелец: вкладка «Владелец» появляется после загрузки, индикатор не уезжает с выбранной вкладки.
5. Студент с заявкой в статусе `Pending`: карточки «Группа» нет; после выхода из аккаунта карточка и аватар очищаются.

## Задача 3: главный экран — чипы, сводка, задания, кольцо, группа, кнопка «+»
