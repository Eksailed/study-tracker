# Роли и группы: план реализации

Статус: в работе, версия 0.8, план от 9 ноября 2026 года. Исполняем «native» (всё в одной сессии), после каждой задачи коммит и `git push origin main`. Сделано: ничего. Спецификация: `docs/specs/роли-и-группы.md`.

Связано: [спецификация](../specs/роли-и-группы.md), [план 0.7](календарь-подзадачи-и-pwa.md), [README](../../README.md).

**Цель.** Четыре роли (владелец, староста, студент, гость), группы с заявками, общие предметы и задания группы с личными отметками и шагами, ссылка для гостей.

**Как устроено.** Групповые предметы и задания живут в тех же таблицах с `OwnerId = NULL` и `GroupId`; личные запросы по `OwnerId` их не видят. Права считает один помощник `GroupAccess` по базе на каждом запросе, любой отказ — `404`. Отметки студентов лежат в `GroupProgress`, их шаги — в `Subtasks.UserId`.

**Технологии.** .NET 10, EF Core + SQLite, xUnit, `WebApplicationFactory`, JS без сборки, Playwright для проверки глазами.

## Общие правила

- Команды: `~/.dotnet/dotnet.exe test tests/StudyTracker.Tests --nologo [--filter X]`; сборка `~/.dotnet/dotnet.exe build --nologo -v q` должна дать «Предупреждений: 0 / Ошибок: 0»; миграции `~/.dotnet/dotnet.exe tool run dotnet-ef migrations add <Имя>`. Перед сборкой остановить запущенный сервер на 5184 (иначе `StudyTracker.dll` заблокирован).
- Сейчас 265 проверок; после каждой задачи все прежние остаются зелёными.
- Тексты ошибок для пользователя — по-русски, ровно как в спецификации.
- Любой отказ в правах — `404` без тела, конфликты состояния — `409` с `{ error }`.
- Мутации (`POST/PUT/DELETE`) идут через cookie и CSRF; токен API на новых адресах — `401` (так уже работает для всего вне `/api/v1`).
- Коммиты по-русски, без строк об авторстве Claude.
- Тесты в `tests/StudyTracker.Tests/`, общие помощники в `Support/GroupSupport.cs` (создаётся в задаче 1 и растёт).

## На что обратить внимание при проверке

Пять случаев, которые легко упустить; у каждого есть тест в своей задаче:

1. Староста А обращается к участникам, ссылке, предметам, заданиям и отметкам группы Б (`404` на каждый адрес) — задачи 3, 5, 7.
2. Студент видит отметки и шаги соседа или старосты: ни в списке, ни по `id` — задачи 5, 6.
3. Групповое задание просачивается в личную ленту `.ics`, Telegram, импорт и `/api/v1` — задачи 5, 7.
4. Права «на лету»: после снятия старосты или выхода студента следующий же запрос уже `404`; отметки и шаги ушедшего стёрты — задачи 3, 4.
5. Миграция на базе со старыми данными теряет строки или связи; `CHECK` пропускает запись без владельца и группы — задача 1.
