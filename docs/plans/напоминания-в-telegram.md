# Напоминания о заданиях в Telegram

Статус: в работе, версия 0.3 от 6 ноября 2026 года. Шаги 1–3 выполнены: хранение, настройки, привязка, расписание и очередь. Проверки используют локальную подмену Telegram и управляемое время. Далее — отправка и ошибки доставки. Настоящий бот не подключён.

Связано: [README](../../README.md), [план аккаунтов](личные-аккаунты.md), [запуск на сервере](../запуск-на-сервере.md), [модели](../../Models.cs), [API](../../Program.cs), [интерфейс](../../wwwroot/app.js), [существующие проверки](../../tests/).

## Идея

Студент подключает свой Telegram в настройках «Зачёта» и получает напоминания перед сдачей. По умолчанию — накануне в 19:00 и в день сдачи в 09:00 по выбранному часовому поясу. Выполненное или удалённое задание больше не должно попадать в новые уведомления.

Работаем с одним экземпляром приложения и текущей SQLite. Сначала доводим один законченный сценарий «подключил → получил напоминание → отключил». Вложения, импорт Obsidian, групповые чаты и управление заданиями из бота в версию 0.3 не входят.

## Как это выглядит для пользователя

1. Открой раздел «Уведомления» и нажми «Подключить Telegram».
2. Перейди по ссылке в бота и нажми «Начать»; ссылка содержит одноразовый код привязки.
3. Вернись в приложение: оно показывает подключение, часовой пояс и два времени напоминаний.
4. Включи уведомления и при желании нажми «Отправить проверочное сообщение».
5. Отключи уведомления временно либо удали привязку полностью.

Привязка ещё не включает автоматические сообщения: нужен отдельный переключатель согласия. В Telegram отправляются только название задания, предмет и дата сдачи. Описание, почта, вложения и сведения о других аккаунтах не передаются. Ссылка на приложение добавляется только при заданном внешнем HTTPS-адресе; `localhost` в сообщения не подставляется.

## Решения по умолчанию

| Вопрос | Решение |
| --- | --- |
| Получение команд бота | `getUpdates` с длительным ожиданием до 30 секунд; без отдельного входящего маршрута Telegram |
| Токен бота | Настройка `Telegram:BotToken`; реальное значение только в переменной окружения или локальных секретах, вне Git и журналов |
| Если токена нет | Приложение работает; раздел уведомлений объясняет, что бот не настроен; фоновые службы Telegram не запускаются |
| Код привязки | 16 случайных байт, кодирование base64url, срок 10 минут; хранить SHA-256 кода, не исходный код |
| Повторная выдача кода | Предыдущий код того же аккаунта перестаёт действовать; не больше 5 выдач за 10 минут на аккаунт |
| Привязка | Только личный чат; один чат на аккаунт и один аккаунт на чат; чужая привязка автоматически не заменяется |
| Часовой пояс | По умолчанию `Europe/Moscow`; в 0.3 также доступны `Asia/Yekaterinburg` и `Asia/Novosibirsk` |
| Время | Накануне в 19:00, в день сдачи в 09:00; каждый вариант можно выключить или изменить с точностью до минуты |
| Включение | По умолчанию выключено, даже после привязки |
| Проверка сроков | Раз в 60 секунд; время хранить и сравнивать в UTC, срок задания остаётся `DateOnly` |
| Пропущенный запуск | Отправлять с задержкой не больше 15 минут; более старые напоминания помечать пропущенными |
| Отправка | Один последовательный обработчик; не чаще одного сообщения в секунду для одного чата |
| Ограничение Telegram `429` | Учитывать `retry_after`; не больше 3 повторов и не позднее 15 минут после времени напоминания |
| Ошибка `400` | Отметить как ошибку, автоматически не повторять |
| Ошибка `403` | Остановить уведомления для привязки, отменить оставшиеся сообщения и показать проблему в настройках |
| Неясный результат | При обрыве связи, таймауте или `5xx` не отправлять автоматически заново: сохранить состояние «Результат неизвестен» |
| Перезапуск во время отправки | Незавершённое состояние `Sending` перевести в `Unknown`, не повторять вслепую |

При обычной повторной проверке очереди подтверждённое сообщение повторно не создаётся. Однако успешную внешнюю отправку и запись результата в SQLite нельзя выполнить одной транзакцией. Если Telegram получил сообщение, а ответ потерялся, приложение не может достоверно установить доставку. Поэтому здесь выбран отказ от автоматического повтора неясного запроса; иногда это означает пропущенное напоминание. Не обещаем доставку «ровно один раз».

Непрерывная работа напоминаний требует включённого приложения и доступа к Telegram. Публикация сайта на домене для получения команд через `getUpdates` не обязательна; для круглосуточной работы понадобится постоянно работающий компьютер или сервер.

## Порядок работ

Каждый шаг — отдельный коммит с обновлением README и строки статуса этого плана. Сохраняем имеющиеся 34 проверки API и 4 проверки контейнеров; новые сценарии добавляем рядом с изменением. Настоящие сообщения при автоматических проверках не отправляем.

### Задача 1: настройки и хранение уведомлений

**Файлы:** `Models.cs`, `Program.cs`, новые `Notifications/NotificationSettings.cs`, `Notifications/TelegramOptions.cs`, `Migrations/`, `tests/test_notifications.py`.

1. Добавь настройки владельца: включение, часовой пояс, два времени и два переключателя периодов.
2. Добавь таблицы привязки чата, одноразовых кодов, состояния получения команд и отправок. Идентификаторы чата храни как 64-битные числа.
3. В истории отправок сохраняй владельца, задание, дату сдачи, вид напоминания, время отправки, число попыток, состояние и возвращённый `message_id`, когда он известен. Не храни копию текста и токен бота.
4. Создай уникальный ключ отправки `(AssignmentId, DueDate, Kind)`. Добавь версию привязки: ожидающая отправка в старый чат должна отменяться после отключения или перепривязки.
5. Примени новую миграцию к копии базы версии 0.2 и проверь сохранность аккаунтов и заданий.

**Тесты:** `test_notification_defaults` — выключено, Москва, 19:00 и 09:00; `test_notification_migration_preserves_accounts` — количество аккаунтов, заданий и их владельцы не меняются; `test_duplicate_reminder_is_rejected` — одна запись на ключ; `test_settings_are_private` — настройки другого владельца недоступны.

**Проверка:** `dotnet build --nologo`, `python -m unittest discover -s tests -v`. Все прежние сценарии и новые проверки проходят; при отсутствии токена обычный вход и задания работают.

**Коммит:** `Добавлены настройки и хранение напоминаний`.

### Задача 2: привязка личного чата по коду

**Файлы:** `Program.cs`, новые `Notifications/TelegramEndpoints.cs`, `Notifications/TelegramClient.cs`, `Notifications/TelegramUpdateWorker.cs`, `tests/test_telegram.py`, `tests/support.py`.

1. Добавь защищённые маршруты просмотра подключения, выдачи кода и удаления привязки. Изменения требуют текущего аккаунта и токена защиты от поддельных запросов.
2. Через `HttpClient` получай сведения о боте и команды `getUpdates`. Сохраняй следующий `offset` после обработки: повтор одного `update_id` не должен заново использовать код.
3. При `/start <код>` проверь тип чата, срок, одноразовость и отсутствие чужой привязки. В одной транзакции используй код и сохрани чат.
4. Не удаляй чужой webhook автоматически: если бот уже настроен на другой способ получения команд, покажи понятную ошибку настройки.
5. Отключи журналирование полного URL клиента Telegram: он содержит токен. Не записывай коды и тела сообщений в журналы или исключения.

**Тесты:** `test_binding_code_expires_after_ten_minutes` — в 9:59 работает, в 10:00 отклоняется; `test_binding_code_is_single_use` — повтор не меняет привязку; `test_new_code_invalidates_old_code`; `test_group_chat_cannot_bind`; `test_chat_bound_to_another_user_is_not_reassigned`; `test_duplicate_update_is_ignored`; `test_telegram_token_is_not_logged` — подставной токен отсутствует в выводе и ошибках.

**Проверка:** `dotnet build --nologo`, `python -m unittest discover -s tests -v`. Получение команд проверяется через локальную подмену Telegram; настоящее подключение пока не требуется.

**Коммит:** `Добавлена привязка Telegram по одноразовому коду`.

### Задача 3: расчёт времени и очередь напоминаний

**Файлы:** новые `Notifications/ReminderPlanner.cs`, `Notifications/ReminderWorker.cs`, существующие `Models.cs`, `Program.cs`, `tests/test_notifications.py`.

1. Рассчитывай два времени отправки из даты сдачи и выбранного пояса. Используй `TimeProvider`, чтобы проверять время без ожиданий в тестах.
2. Раз в 60 секунд создавай недостающие записи очереди в пределах 15-минутного окна. Уникальный ключ должен защищать и от повторного прохода, и от перезапуска.
3. Перед отправкой повторно проверяй владельца, привязку, её версию, включение и актуальную дату задания.
4. При выполнении, удалении, смене срока или настроек отменяй ещё не отправленные неактуальные записи. Уже подтверждённые сообщения не отправляй заново после возврата прежней даты или повторного подключения чата.
5. Не отправляй напоминания о датах раньше текущей местной даты. После долгой остановки не отправляй накопившиеся старые сообщения.

**Тесты:** `test_moscow_reminder_times` — для срока 12 ноября 2026 года: 11 ноября 19:00 МСК = 16:00 UTC, 12 ноября 09:00 МСК = 06:00 UTC; `test_restart_does_not_duplicate_reminder`; `test_completed_assignment_is_not_notified`; `test_changed_due_date_cancels_old_pending_reminder`; `test_disconnected_chat_cancels_pending_reminders`; `test_missed_window_is_skipped` — 14:59 задержки допускается, 15:00 уже пропускается.

**Проверка:** `dotnet build --nologo`, `python -m unittest discover -s tests -v`. Все временные сценарии выполняются с управляемым временем; запуск тестов не ждёт наступления реального срока.

**Коммит:** `Добавлен расчёт сроков и очередь напоминаний`.

### Задача 4: отправка и ошибки доставки

**Файлы:** `Notifications/TelegramClient.cs`, `Notifications/ReminderWorker.cs`, новые `Notifications/ReminderSender.cs`, `tests/test_telegram.py`.

1. Отправляй обычный текст через `sendMessage`, без интерпретации HTML или Markdown из названия задания.
2. Формируй сообщение из названия, предмета и полной даты сдачи. Название и предмет уже ограничены длиной в существующем API; описание не добавляй.
3. Дай запросу отправки таймаут 10 секунд. Для ожидания `getUpdates` используй отдельный таймаут 40 секунд, чтобы не обрывать 30-секундное ожидание команды.
4. Реализуй обработку `429`, `400`, `403`, таймаута и неясного результата по таблице решений. Перед новым запросом сохраняй `Sending`; после подтверждения — `Sent` и `message_id`.
5. Не обещай отмену запроса, который уже ушёл в Telegram: отключение отменяет ожидающие отправки, но полученное сообщение отозвать этим переключателем нельзя.

**Тесты:** `test_successful_send_records_message_id`; `test_429_respects_retry_after` — следующий запрос не раньше указанной паузы; `test_retry_limit_is_three`; `test_403_disables_delivery`; `test_timeout_is_unknown_without_automatic_retry`; `test_restart_marks_inflight_send_unknown`; `test_reminder_contains_only_allowed_fields` — почты и описания в сообщении нет.

**Проверка:** `python -m unittest discover -s tests -v`. Подмена Telegram возвращает все перечисленные ответы; число запросов и моменты повторов совпадают с правилами. Ни одного обращения к настоящему Telegram в CI.

**Коммит:** `Добавлена отправка напоминаний с учётом ошибок Telegram`.

### Задача 5: настройки уведомлений в интерфейсе

**Файлы:** `wwwroot/index.html`, `wwwroot/app.js`, `wwwroot/app.css`, `Notifications/TelegramEndpoints.cs`, `tests/test_notifications.py`.

1. Добавь раздел «Уведомления»: статус подключения, ссылка в бота, срок действия кода, часовой пояс и два времени.
2. После перехода в Telegram проверяй статус раз в 5 секунд, только пока раздел открыт и код не истёк. Прекращай опрос при закрытии раздела, выходе и смене аккаунта.
3. Добавь включение, временное выключение и удаление привязки. Если бота нет, покажи причину и не предлагай неработающее подключение.
4. Добавь кнопку проверочного сообщения: один запрос не чаще раза в минуту на аккаунт, только при активной привязке. Отправка происходит по явному нажатию пользователя.
5. Показывай последнее состояние доставки: отправлено, ошибка или результат неизвестен. Не выдавай неизвестный результат за доставленное сообщение.

**Тесты:** `test_notification_settings_require_csrf`; `test_invalid_timezone_is_rejected` — неизвестный пояс получает `400`; `test_test_message_is_rate_limited` — повтор раньше минуты получает `429`; `test_disconnect_clears_pending_code`. В браузере проверь подключение к подмене, сохранение времени, выключение, выход и вход в другой аккаунт; данные предыдущего чата не появляются.

**Проверка:** `node --check wwwroot/app.js`, `python -m unittest discover -s tests -v`; затем клавиатура и ширина 320, 390 и 1440 пикселей в браузере. Временное выключение должно сохранять саму привязку.

**Коммит:** `Добавлены настройки Telegram и времени напоминаний`.

## Когда версия готова

- Пользователь подключает только свой личный чат; код одноразовый и истекает через 10 минут.
- Включение уведомлений требует отдельного действия пользователя.
- Напоминания приходят по выбранному времени, завершённые задания исключены.
- Перезапуск не создаёт повтор подтверждённой отправки; неизвестный результат отображается честно.
- Отключение отменяет ожидающие сообщения, аккаунты не видят чужие настройки.
- Отсутствие токена или сбой Telegram не мешают входу и работе с заданиями.
- Все исходные и новые проверки проходят; README описывает подтверждённый результат и ограничения.

## Что проверено при составлении

Прочитаны текущие `Models.cs`, `Program.cs`, README и GitHub Actions. В версии 0.2 уже есть владельцы заданий, миграции и контейнерные проверки; таблиц и служб уведомлений пока нет. В этой задаче меняется только документация: новые функции, тесты и отправка сообщений не выполнялись.

Способ работы с командами, полями ответа и отправкой сверяется с [официальным Telegram Bot API](https://core.telegram.org/bots/api#getupdates). Числа, расписание, ограничения версии и политика неясной доставки выше — проектные решения для «Зачёта».
