## Подключение бота

Пользователь создаёт своего бота через BotFather и получает токен. Приложение работает с Bot API напрямую по HTTPS. Получение команд выполняется через `getUpdates` с ожиданием до 30 секунд; входящий маршрут Telegram и публичный домен для этого не нужны.

При запуске через Docker запиши реальное значение `TELEGRAM_BOT_TOKEN` только в локальный `.env` рядом с `compose.yaml`. Пример в `.env.example` оставлен пустым. Затем пересоздай приложение:

```sh
docker compose -p zachet up -d --no-deps --force-recreate app
```

Токен передаётся только сервису `app`. Сервис `migrate` его не получает и не запускает службы бота. Для обычного запуска .NET используется переменная окружения `Telegram__BotToken`. После изменения переменной приложение нужно перезапустить.

Без токена всё, что связано с заданиями и аккаунтами, продолжает работать; раздел «Уведомления» показывает, что бот не настроен. Некорректный токен не открывает подключение. Полные URL клиента Telegram и необработанные сетевые исключения не записываются в журнал, поскольку URL содержит токен.

Если у бота уже настроен webhook, приложение сообщает об этом и не удаляет его. Используй отдельного бота либо самостоятельно отключи прежнюю настройку. Одним ботом должен управлять один запущенный экземпляр «Зачёта».

## Привязка личного чата

1. Войди в «Зачёт» и открой «Уведомления».
2. Нажми «Подключить Telegram», затем «Открыть бота в Telegram».
3. В личном чате нажми «Начать». Бот подтвердит подключение.
4. Вернись в приложение и дождись статуса «Личный чат подключён» либо нажми «Обновить».
5. Отдельно включи «Отправлять напоминания в Telegram» и сохрани настройки.

В ссылке — 16 случайных байт в base64url. Код используется один раз и действует 10 минут; в базе хранится только SHA-256. Новая ссылка отменяет старую. Разрешено не больше 5 выдач за 10 минут на аккаунт. Групповые чаты не принимаются; уже занятый чужой чат не заменяется.

Временное выключение напоминаний сохраняет привязку. «Удалить привязку» отключает уведомления, удаляет чат и код, отменяет ожидающие сообщения. Для нового чата сначала удали прежнюю привязку. Уже ушедший запрос на отправку отменить этим действием нельзя.

## Время и содержимое

По умолчанию напоминания выключены. После подключения доступны два периода: накануне в 19:00 и в день сдачи в 09:00. Время можно изменить с точностью до минуты; доступны Москва, Екатеринбург и Новосибирск. Часовой пояс выбирается в настройках и не зависит от пояса браузера.

Планировщик проверяет сроки раз в 60 секунд. Дата сдачи остаётся календарной датой, а время отправки хранится в UTC. Например, для Москвы 19:00 — это 16:00 UTC. Если приложение опоздало меньше чем на 15 минут, уведомление ещё можно отправить; в 15:00 задержки и позже оно пропускается. Старые сообщения после долгой остановки не рассылаются.

В сообщении есть название задания, предмет и полная дата сдачи. Описание, почта и вложения не передаются. Текст не интерпретируется как HTML или Markdown. Ссылка на приложение добавляется только при заданном HTTPS-адресе без учётных данных, параметров и фрагмента; адрес `localhost` исключается. В Docker адрес берётся из `DOMAIN`, при обычном запуске — из `Telegram__PublicUrl`.

Выполненное или удалённое задание не отправляется. Изменение даты, времени, привязки или выключение уведомлений проверяется повторно перед сетевым запросом. Подтверждённое сообщение для того же задания, даты и периода не создаётся повторно после перезапуска.

## Проверочное сообщение

Нажми «Проверочное сообщение» при подключённом рабочем чате. Автоматические напоминания можно оставить выключенными. Кнопка ставит сообщение в очередь; статус «Отправлено» появляется только после подтверждения Telegram. Ограничение — один запрос в минуту на аккаунт.

В браузере ссылка и опрос состояния существуют только пока открыта форма. После закрытия, выхода или смены аккаунта они очищаются. Во время ожидания подключения состояние обновляется раз в 5 секунд, до истечения кода. Настройки другого аккаунта не подставляются в старую форму.

## Результаты доставки

| Состояние | Что означает |
| --- | --- |
| `Pending` | Ожидает времени отправки или разрешённого повтора |
| `Sending` | Попытка записана в базу, выполняется запрос Telegram |
| `Sent` | Telegram подтвердил отправку; сохранён `message_id` |
| `Failed` | Подтверждённая ошибка; автоматической отправки больше нет |
| `Unknown` | Нельзя установить, получено ли сообщение; повтор не выполняется |
| `Cancelled` | Изменилось задание, расписание, привязка или согласие |
| `Skipped` | Окно отправки истекло |

При `429` отправка переносится на паузу `retry_after`, но не позднее конца 15-минутного окна. Допускаются 3 повтора после первого запроса. При `400` автоматического повтора нет; `403` выключает доставку для текущей привязки и показывает предложение переподключить Telegram.

Таймаут отправки — 10 секунд; для длительного ожидания команд используется отдельный клиент с таймаутом 40 секунд. Обрыв связи, таймаут и `5xx` приводят к `Unknown`. После перезапуска незавершённое `Sending` тоже становится `Unknown`.

Telegram и SQLite не участвуют в общей транзакции. Если сообщение дошло, а подтверждение потерялось, нельзя достоверно отличить доставку от неудачи. Выбран отказ от автоматического повтора такого запроса: это снижает риск дубля, но иногда означает пропущенное напоминание. Доставка ровно один раз не гарантируется.

## Проверки

```sh
dotnet build --nologo
node --check wwwroot/app.js
node --check wwwroot/notifications.js
python -m unittest discover -s tests -v
docker build -t study-tracker:local .
python tests/test_deployment.py
```

Обычные проверки используют временные базы и подмену Telegram на локальном HTTP-сервере. Проверяются срок и одноразовость кода, разграничение аккаунтов, расписание с управляемым временем, ошибки доставки, очередь, согласие и ограничение проверочного сообщения.

Контейнерные проверки используют отдельный тестовый сервис Telegram. В нём проверяются сохранение привязки и подтверждённой отправки после пересоздания приложения и отсутствие обращений к боту из команды миграции. Этот сервис не добавляется в рабочий `compose.yaml`, не принимает настоящий токен и удаляется вместе с временным проектом.

Для проверки времени используются параметры `Testing:UtcNow` и `Telegram:ManualMode`, доступные только в Development; подмена адреса Bot API через `Telegram:ApiBase` также работает только в Development. В обычной эксплуатации они не задаются. Команды `--telegram-poll`, `--notifications-plan` и `--notifications-tick` используются тестами для одного прохода; не запускай второй обработчик параллельно рабочему экземпляру приложения.

Настоящая отправка проверяется отдельно после настройки своего бота и явного указания пользователя отправить проверку в выбранный чат. В текущем выполнении использовалась только подмена; фактическая доставка через Telegram пока не проверена. Для круглосуточных напоминаний приложение должно постоянно работать и иметь доступ к Telegram.

Справочник протокола: [Telegram Bot API](https://core.telegram.org/bots/api).
